# Candidate Hazard-Based Red Zone Generation Module (Step 7)

## Overview & Purpose
This module implements **Step 7: Candidate Hazard-Based Red Zone Generation** for project **SIH26191** (*Intelligent Identification of Hazard-Based Red Zones, Carrying Capacity Assessment, and Immediate Relocation Needs for Vulnerable Habitations*) in the primary pilot area of **Rudraprayag District, Uttarakhand, India**.

The core objective of this module is to transform the discrete raster pixels classified as **Higher Multi-Hazard Indicator** (Class 3) from Step 6 into meaningful, contiguous, and spatially grouped polygon entities: **Candidate Hazard-Based Red Zones**.

---

## Processing Pipeline Workflow

```
[ Step 6 Multi-Hazard Raster Outputs ]
  ├── multihazard_score.tif (Continuous Score [0.0, 1.0])
  ├── multihazard_classes.tif (Class 1, 2, 3)
  ├── terrain_contribution.tif (0.5 * Slope Proxy)
  └── flood_contribution.tif (0.5 * Flood Proxy)
                         │
                         ▼
1. Input Selection & Binary Mask Creation
   - Extract pixels matching configured source class (Class 3: Higher Multi-Hazard Indicator)
                         │
                         ▼
2. Connected Components Segmentation
   - Deterministic spatial grouping using configured connectivity (default: 8-neighbour)
   - Assign preliminary contiguous region identifiers
                         │
                         ▼
3. Minimum Mapping Unit (MMU) / Area Filtering
   - Calculate exact geographic area for each contiguous component in projected CRS (EPSG:32644)
   - Filter out isolated micro-clusters below the configured `minimum_zone_area_m2` threshold
   - Transparently record initial count, removed count, and retained count
                         │
                         ▼
4. Vectorization & Geometry Construction
   - Convert retained raster pixel clusters into valid vector multipolygons/polygons
   - Ensure clean geometries conforming to analysis CRS (EPSG:32644)
                         │
                         ▼
5. Zonal Raster Attribution & Explainability
   - Extract exact underlying pixel statistics for each zone:
     • mean_multihazard_score, max_multihazard_score, min_multihazard_score
     • terrain_contribution_mean, flood_contribution_mean
     • pixel_count, area_m2, area_hectares
                         │
                         ▼
6. Deterministic Priority Ranking
   - Rank candidate zones deterministically:
     Primary: Mean Multi-Hazard Score (descending)
     Secondary: Max Multi-Hazard Score (descending)
     Tertiary: Area (descending)
   - Assign sequential `candidate_priority_rank` and deterministic `zone_id` (e.g. `RZ-001`)
                         │
                         ▼
7. Multi-Format Vector Export
   - OGC GeoPackage: `data/outputs/candidate_hazard_based_red_zones.gpkg`
   - OGC GeoJSON   : `data/outputs/candidate_hazard_based_red_zones.geojson`
```

---

## Configuration-Driven Parameters
All operational parameters are read dynamically from `configs/project.yaml` under the `redzones` section:
- `source_class`: Source multi-hazard class code (3 = Higher Multi-Hazard Indicator)
- `connectivity`: Morphological connectivity (8 for 8-neighbour, 4 for 4-neighbour)
- `minimum_zone_area_m2`: Minimum mapping unit threshold in square metres
- `output_vector`: Primary vector output path (GeoPackage)
- `output_geojson`: GeoJSON export path
- `labels` & `disclaimer`: Configured standardized terminology

## Critical Terminology & Legal Disclaimer

> [!IMPORTANT]
> **Decision-Support Classification Only**
>
> The outputs generated by this module are **Candidate Hazard-Based Red Zones** intended strictly as a **screening and decision-support tool**.
>
> They are **NOT**:
> - Official government-declared Red Zones
> - Legally binding hazard delineations
> - Evacuation orders or notices
> - Relocation mandates or authorizations
> - Engineering or geotechnical safety certifications
> - Guarantees or statistical forecasts of disaster occurrence
>
> All candidate zones require **mandatory ground-truthing, geotechnical site investigation, and official administrative verification** by statutory disaster management authorities (e.g., USDMA, NDMA, District Administration).

## Scientific Limitations
1. **Screening Model Basis**: Candidate zones represent purely terrain-derived (slope gradient) and hydrology-derived (topographic wetness) predisposing spatial patterns.
2. **Exclusion of Dynamic Variables**: Real-time rainfall intensity, localized structural geology, faults, soil stratigraphy, deforestation, and anthropic construction cuts are not yet incorporated.
3. **Threshold Sensitivity**: The spatial extent and number of candidate zones depend on DEM spatial resolution (Copernicus GLO-30 ~30m), proxy normalizations, class cutoffs (0.65 threshold), and MMU area filtering.
